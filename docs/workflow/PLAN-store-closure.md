# Plan — ปิดสาขา (Store closure)

Feature slug: `store-closure`
Date: 2026-10-11
Status: planning done → `/design`

## Goal
สาขาที่ปิดไปแล้ว (เช่น 51512 Seacon Square) ยังโผล่ทุกหน้า นับรวมในตัวเลข และถูกเฝ้า DVR ทั้งที่ไม่มีเครื่องแล้ว
เป้าหมาย: HQ ปิดสาขาได้จากหน้าเว็บ แล้วสาขานั้นหายจากงานประจำวันทุกหน้า แต่ยังค้นดูประวัติได้ใน Asset Register

## Users and roles
- `hq_admin` (Bata IT) — ระบบเป็น single-role: ปิด / เปิดสาขาอีกครั้งได้, ดูสาขาที่ปิดใน Asset Register
- สคริปต์ `tools/ivms-monitor` (service_role) — อ่านสถานะปิดเพื่อข้ามสาขานั้น ไม่แก้ค่านี้

## Scope
**In scope**
- ปุ่ม "ปิดสาขา" / "เปิดสาขาอีกครั้ง" ในหน้า Edit Detail ของสาขา พร้อมวันที่ปิดและเหตุผล
- ซ่อนสาขาที่ปิดจากทุกหน้า ยกเว้น Asset Register (ตัวกรอง + ป้ายเทา "ปิดสาขา")
- ตัวเลข 194 ที่เขียนตายตัว → นับจากสาขาที่เปิดอยู่
- สคริปต์ iVMS ข้ามสาขาที่ปิด; ถ้ายังเจอเครื่องของสาขาที่ปิดใน iVMS → แท็บ Rollout "ต้องตรวจ"
- ปิดสาขาชุดแรกด้วย SQL จากรายชื่อที่ผู้ใช้ส่งให้ (ครั้งเดียว)

**Out of scope**
- ลบสาขาออกจากฐานข้อมูล (ข้อมูลประวัติ/ใบงานต้องอยู่ครบ)
- ย้ายเครื่อง DVR ของสาขาที่ปิดไปสาขาอื่นอัตโนมัติ (ใช้ "Move Device" เดิมด้วยมือ)
- หน้า Installation Project (อยู่อีก branch ยังไม่ merge) — ทำตามหลัง merge ถ้าจำเป็น
- ฟอร์ม Payslip / ระบบอื่นนอก Command Center

## Requirements
- **R1 ปิดสาขา** — ใน Edit Detail มีปุ่ม "ปิดสาขา" → ใส่วันที่ปิด (ค่าเริ่มต้น = วันนี้) และเหตุผล (บังคับ) → ยืนยัน
- **R2 เปิดสาขาอีกครั้ง** — สาขาที่ปิดอยู่มีปุ่ม "เปิดสาขาอีกครั้ง" (ยืนยันก่อน) ข้อมูลเดิมกลับมาครบ
- **R3 บันทึกว่าใครปิด/เปิดเมื่อไร** — เก็บผู้ทำและเวลา ดูได้ในหน้าสาขา
- **R4 ซ่อนจากงานประจำวัน** — Dashboard, Device Status (ทุกแท็บ), Work Orders (สร้างใหม่ / รายการรอทำ), Survey, Reports และรายการ "Move to store…" ไม่แสดงและไม่นับสาขาที่ปิด
- **R5 Asset Register** — ค่าเริ่มต้นแสดงเฉพาะสาขาที่เปิด; ตัวกรอง "แสดงสาขาที่ปิด" แสดงสาขาที่ปิดพร้อมป้ายเทา "ปิดสาขา dd/mm/yyyy"; หน้า Details ของสาขาที่ปิดยังเปิดได้ (เข้าตรงจากลิงก์/ค้นหา) พร้อมแถบบอกว่าปิดแล้ว
- **R6 ตัวเลขรวม** — "เฝ้าอยู่ X / 194" และ % ในแท็บ Rollout ใช้จำนวนสาขาที่เปิดอยู่จริง
- **R7 สคริปต์ iVMS** — ไม่อ่าน/ไม่อัปเดต/ไม่ส่งเมลของสาขาที่ปิด; การหลุดที่ยังเปิดค้างของสาขานั้นถูกปิดตอนปิดสาขา; ถ้าเจอเครื่องรหัสสาขาที่ปิดใน iVMS → อยู่ใน "ต้องตรวจ" (ลบเครื่องออกจาก iVMS)
- **R8 Export** — Excel/PDF ของ Asset Register ตามตัวกรองที่เลือก (ปิดอยู่ = มีคอลัมน์สถานะสาขา)
- **R9 ปิดชุดแรก** — SQL ครั้งเดียวจากรายชื่อรหัสสาขาที่ผู้ใช้ส่ง มีขั้น "ดูก่อน" และไม่ลบข้อมูล

## Data
- `stores.is_active boolean default true` — **มีอยู่แล้ว** (schema.sql) แต่หน้าเว็บยังไม่ใช้เลย; สคริปต์ iVMS กรองอยู่แล้ว (`supa.load_stores`)
- เพิ่มใน migration ใหม่ (`025_store_closure.sql`): `closed_at date`, `close_reason text`, `closed_by uuid → profiles(id)`; ประวัติปิด/เปิด — ตารางเล็ก `store_status_history` (store_id, action open/close, at, by, reason) หรือใช้ audit ที่มีอยู่ถ้ามี (ตรวจตอน `/design`)
- ตอนปิด: `store_monitor.monitored = false`, ปิด outage ที่ยังค้าง (`ended_at = now`, note "ปิดสาขา") — ทำใน function เดียวฝั่ง DB เพื่อไม่ให้ค้างครึ่งทาง
- จุดกรองหลักฝั่งเว็บ: `AppDataProvider` (`allStores` → `stores` memo) — กรองที่เดียว ให้ Asset Register ใช้รายการที่รวมสาขาที่ปิด
- รายชื่อสาขาที่ปิดจริง: **ยังไม่มี** — ต้องได้จากผู้ใช้

## Risks and open questions
1. **รายชื่อสาขาที่ปิด** — นอกจาก 51512 Seacon Square มีสาขาไหนอีก (และวันที่ปิดถ้ารู้)
2. Work Order / ใบซ่อมที่ยังเปิดค้างของสาขาที่จะปิด — ปิดสาขาได้เลยหรือต้องปิดงานก่อน (เสนอ: เตือนแต่ไม่บล็อก)
3. Reports ย้อนหลัง (ช่วงวันที่ก่อนปิด) ควรนับสาขานั้นไหม (เสนอ: Reports ตอนนี้ดูสถานะปัจจุบัน → ไม่นับ; ประวัติการหลุดยังอยู่ในแท็บประวัติถ้าเลือกช่วงวันเก่า)
4. RLS: การปิด/เปิดต้องผ่าน function ที่ตรวจ `is_hq_admin()` ไม่ให้ update `is_active` ตรงจาก client โดยไม่มีบันทึก
5. Branch: Device Monitoring ยังไม่ merge (`feat/asset-register-device-dot`, PR #2) และ Installation Project อยู่อีก branch — งานนี้จะต่อจาก PR #2 เพราะแตะ Device Status / สคริปต์
6. `CLAUDE.md` บน branch นี้ยังเป็นของโปรเจกต์ Payslip — ไม่ใช้อ้างอิง

## Milestones
1. M1 — Migration 025 + function ปิด/เปิด + SQL ปิดชุดแรก (ใช้ได้ทันทีแม้หน้าเว็บยังไม่เสร็จ: สคริปต์ข้ามสาขาที่ปิดแล้ว)
2. M2 — กรองสาขาที่ปิดใน `AppDataProvider` + ตัวเลข 194 → นับจริง (R4, R6)
3. M3 — Asset Register: ตัวกรอง + ป้าย + แถบในหน้า Details + ปุ่มปิด/เปิดใน Edit Detail (R1–R3, R5, R8)
4. M4 — สคริปต์: ปิด outage ค้าง + "ต้องตรวจ" สำหรับเครื่องของสาขาที่ปิด (R7) + ทดสอบ state
